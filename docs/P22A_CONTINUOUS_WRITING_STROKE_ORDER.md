# P2.2a — 连续写完整个字，最后检查笔顺（工程预览）

状态：2026-10-12 用户新要求，替代 P2.1c 的“每一笔须手动确认”交互。跟踪 Issue #145；设计基线是 PDF v0.5.1、A3 201 字/1045笔、真实蓝墨 P2.1b 和 IndexedDB P2.1c。

## 交互决策

1. 学习者点击田字格进入沉浸临摹，自然依次书写，不再显示或要求“确认这一笔”。每一次真实 pointerup 只要采样有效，即自动形成一条不可改写的原始轨迹，保留蓝墨并更新已写笔数，下一笔立即可写。
2. 达到书中该字的标准笔画数量后，自动从整字轨迹**推断每条学习者笔画实际对应的参考笔画**，检查它们是否按已审顺序依次出现。绝不能仅用“第 n 次提笔 = 参考第 n 笔”的假定。
3. 反馈分为：**符合参考笔顺（工程匹配）**、**疑似先后顺序有误**、**无法可靠判断**。笔数不足时不谎报正确，提示还差几笔。不能直接声称书法教师判定正确，源 median 是未经真人教学审批的轨迹参考。
4. 原始输入笔迹、撤销上一笔、重新写整个字（二次确认）、当前笔高亮参考、可选查看上一笔/下一笔参考、索引防串联和本机 IndexedDB 恢复不变。手指、触控笔或鼠标可用；输入过程中无轮廓磁吸、自动补墨。
5. 一次写错可撤销最后一笔重写；整字写完后也可撤销，结果同步清除并在再次写完后重算。保存草稿/学习记录绝不向云端上传，用户本机当前浏览器保存。

## 匹配器与判据

新文件 `animation/practice/order-check.js` 是独立纯算法模块；既有 `timeline.js` 原字形只读，不替换 A3 观赏动画。参考 `stroke.median` 的**空间位置**和采样点，计算起笔位置、收笔位置、对齐形态与相对行程距离，按来源坐标归一化（SVG `translate(0 900) scale(1 -1)` 的逆映射早已由 P2.1b 提供）。

算法不是逐条输入强行与相同索引比较，而是对完整 N×N 的轨迹相似度矩阵做一对一**全局最小代价分配**：N<=18 时使用子集 DP，得到输入序列真正最像哪些来源笔画。例如“水”按参考笔画 2、1、3、4 的顺序写四笔，应判定为 `reordered`，而不是 `consistent`。给结果附加低匹配代价与相邻候选的区别阈值；位置重合、折钩近似、来源中线不稳定、笔画似是而非时**返回 `uncertain`，而不是强判错误**。

这不是成熟的正式书法评测：只初步检查**笔画先后次序**，不评价运笔美学、笔压真伪、速度或书写力度。参考 medians 未经真人书法教研审定；在实际 Pad 触控笔和真实学习者数据标定前，UI 明示“工程提示”，不可用它进行分数、考试或惩罚。

## 模型与存储

- `animation/practice/whole-progress.js` 在 pointerup 时自动保存 `raw-captured`（学习者原始位置/时间/设备笔压来源）；序号只是第几次自然落笔，**不代表它是标准第几笔**，直到整字后 matcher 才给出独立判断。
- 新 IndexedDB snapshot 为 `schemaVersion:2, written:[...]`。沿用原 `zitie-guided-practice-v1` local DB 与 PDF SHA/main_id/字形 SHA 复合键，存储层支持新/旧两种 schema。旧的 P2.1c `userConfirmed` 按受限字段校验后以 `legacyImported` 只读保留；不把人工确认自动升级成“检测正确”的记录。要获得本次的整字顺序判断，建议完整重写。
- 页面恢复记录时重新运行当前 matcher，不把某一版阈值产生的 verdict 当作永久事实写入数据库；将来调整判断算法不会悄悄改原始手写轨迹。
- `trace-canvas.js` 继续从实际样点绘制所有蓝色笔画，DPR/平板旋转与撤销都要重绘，不改 PDF 原轮廓。

## 测试和上线门槛

1. 真实 PDF 201/1045 全量**源轨迹正例**：各字的参考 medians 按原顺序输入，不能错判交换；“水”交换先后、逆序、乱涂和重复重叠分别测试 swapped/uncertain，不允许错误放行。
2. 真实 Chromium 浏览器：手指/pen/mouse 自然提笔自动续写，不再需要笔画确认；水4笔自动判断、故意交换笔顺识别、撤销结果复位、保存/刷新恢复、整字重练、Touch cancel、多屏幕墨迹坐标保持。
3. 原生 Chromium CDP `Input.dispatchTouchEvent`：按水字全4笔触摸写完，屏幕蓝墨、结果、DPR2、IndexedDB Reload 后同一结果、撤销与换顺序负例全通过；该浏览器触摸测试不能替代 Apple Pencil/Android Pad 实机硬件验收。
4. 不能更改正式 PDF 299页、manifest、B01–B21 数据、已审核来源字形、A3.6 原笔尖前缘或双笔压动画；原 Node/Chromium/A3.9/Book 完整 CI 保留。
5. 最终 PR HEAD 精确 SHA 的 A1 Chromium + Book 双 CI 完成 success 后方可合并；同一 `main` merge SHA 的 Pages **Configure + Upload + 实际 Deploy** 都 success 才宣称 Web 发布。
