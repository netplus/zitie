# A3.6：201字 / 1045笔墨迹前缘与笔尖同步

跟踪 [Issue #125](https://github.com/netplus/zitie/issues/125)。用户观察到「水」等字红色墨迹填充先于可见笔尖到达。这不同于既有的“已绘红墨不会消失”断言；仅调整笔速不能解决提前填墨。

## 全源几何诊断

正式 v0.5.1 字帖：299页，B01—B21，共201个主部首、1045笔，原SVG轮廓以及来源median已被冻结。原brush-union遮罩会把宽笔触圆头并集与原SVG相交；上一节圆头可能越过折角，盖住较远的后续中线。之前的视觉前缘修正只针对已审的折/钩，最多96单位，且把标记退后4单位，不能限制实际着墨。

独立的几何分析使用正式book-pack.js，逐笔展平原SVG贝塞尔并按原遮罩半径模拟，覆盖1045笔、每笔13处空间位置。源几何估计显示水第二笔横撇可提前约168 SVG单位、第一笔竖钩约120，口第二笔横折约75，月第二笔横折钩约105。此处数字是**离线几何估计**，不是Chromium真实像素证据或真人运笔数据；正式验收须另做实际网页光栅测试。

## Source arc Voronoi 显墨屏障

采用显式选择的 StrokePlayer frontGuard 模式：**不重画笔迹**，仍用旧独立圆头遮罩避免过去的填充漏洞，只额外用source median距离裁剪可见墨迹。

每条中线以间距不大于4个SVG单位取样，按“哪个采样站点最近”形成二维Voronoi凸多边形分区；只有虚拟笔尖已经经过对应站点，才把该区加入SVG clipPath。于是正在写时的红墨等于**原SVG轮廓 ∩ 旧圆头遮罩 ∩ 已到达区域并集**。后一限制阻止之前的大圆头在折角把未来中线提前染红；光标保持在原始中线真实进度位置，而不是跳跃性前挪。所有已到达分区严格累积；seek倒放则按到达前缀隐藏。0%不显墨，写满100%显完整原始SVG轮廓，绝不改变PDF源文件。

数学上，距离未来中线点零距离的后续站点优先拥有其Voronoi区，因此前序站点不应把该中心线点误染；唯一的空间重访相同点遵循“第一次已落墨”的规则。注意此约束针对沿轨迹未来方向的提前填墨，不等于物理大笔刷接触区域的每一个侧向边缘都与可见小圆笔尖精确重合。

实测Node离线全源：201字/1045笔，共130570个4单位站点，0空分区，全部测试的后续距离至少12单位的站点没有被提前区占有。分区图不是新的笔画数据，只是播放视觉剪裁派生物。

1. Node新a36-front-guard.test.cjs覆盖1045笔、源不变、采样边界、合法Voronoi分区、单调渲染与倒拖、异常fail-closed。
