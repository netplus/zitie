# P9.3 GF 3002—1999 二次取证结果（2026-10-27）

**结论：未取得覆盖 37 个特殊主部首的完整国家规范序列表；其实际规范正确性仍然阻断。** 本轮定位了一处此前误判风险：不能把“存在 GF 3002 标准”当作“其全部 20902 个汉字笔顺表已经取得”。

## 1. 实际取得了什么

- 教育部网页：[GF 3002—1999 发布说明](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201001/t20100115_75619.html)；此前台账中的教育部附件链接 `https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201001/W020150902457900316281.pdf` **在真实 GitHub Actions 执行期间连续返回 HTTP 404**，不能在台账中描述为已取得当前官方原始字节。
- 公开第三方档案 [zispace/hanzi-docs 中的 GF 3002—1999 PDF](https://github.com/zispace/hanzi-docs/tree/main/%E4%B8%AD%E5%9B%BD%E5%A4%A7%E9%99%86/2-GF-%E8%AF%AD%E8%A8%80%E6%96%87%E5%AD%97%E8%A7%84%E8%8C%83) 真正已下载，文件尺寸 **6,730,497 B**，SHA256 **`cb5cb74f108dafed41a3583bc8d33d8dd318d1a21d714923c0f1ced89443cf3e`**。
- 用固定 PyMuPDF 1.26.7 核查，**该档案只有 8 页，8页皆为扫描图片，无任何可提取文本或UCS码的原生字符层**。人工查看了实页图：第一页为上海教育出版社的GF 3002封面，第5页为规范正文节选，第8页为附录笔顺数据表的开头，末尾出现“（略）”；**20902字的完整明细没有包含在这份文件里**。
- 数据层直接定位出的完整37个主字原始规范五类码：**0/37**。这不是说37字没有标准编码，而是**当前能够独立取得的源文件不足以逐项复核**。部分早期码位虽然能在最后一页影像看到，扫描质量、原表缺页和人工未双审都不允许当成37项完整原表证据。

证据：[P9.3实际CI及五张抽样页面](https://github.com/netplus/zitie/actions/runs/40505489038)（修正流程后新的CI见PR最后检查），提取器 `scripts/p9_GF3002_original_pdf_probe.py`。它保护标准档案文件SHA并禁止将仅8页残缺副本静默升级成规范原始全表。

## 2. 为什么本轮不自动填充笔顺与名称

GF 3002中的基本五种笔形编码只告诉大类序列，不能判断折、提、弯、竖钩、组合折笔是否应怎样分类、书写，也不能代替GF 2001的具体细笔形及人民教育出版社示范字形。因此 `data/cultural_edition/p9_normative_open_cases_37_83.json` 中37字官方原表缺证、83处具体细笔名、子字第二笔争议仍保留阻断；新 P10 校对稿已暂停显示“子”字不一致的旧教学文字，但历史 v0.5.1 和原1045幅源图不可修改。

## 3. 下一步真正需要的独立材料

要关闭37项，必须找到**包含GF3002 20902字完整排序和笔顺码的原始附录/正式电子文件**，逐项记录物理页、UCS、印出的五码、该列内容图像证据及来源SHA，并与旧笔顺独立对照。如果教育部当前附件无法下载，应选有明确原书版本及授权的图书馆馆藏/出版社版，并标记非官方字节认证，不可冒称已对教育部本体取得SHA。

**本PR只修复规范来源事实、产生可重复的原始资料可用性证据和保持不批准门禁，不是 GF3002 37字笔顺复核完成。**
